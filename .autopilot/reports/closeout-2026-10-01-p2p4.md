## P2 — Task OS iteration 2 (three measured turn-burners)

Root causes found by tracing the loop, not by guessing:

1. `read_file`'s unchanged-window stub claimed "the content from the earlier read
   is still current" even when the output budget had elided the middle — so the
   model re-read blind. Reuse state is now three-way (miss / fresh / truncated),
   truncated windows get an honest stub, and elision notices carry a per-tool
   recovery hint ("re-read only it with offset/limit").
2. `todo_write` and the unified runtime plan were maintained in parallel (two
   checklists). A live task that owns a plan now redirects `todo_write` to
   `task_plan_update`, and the todo nudge stays silent once the run has
   `task_define`d. The guard is deliberately narrow: a stale draft with an empty
   plan does **not** disable the tool.
3. Capability discovery accepted `mcp-tool` candidates, but `moss task run` only
   ever fed it skills + builtins — MCP was never selected per task. The MCP
   inventory is now split out by wire name, scored per goal, rendered with its
   server, and unmatched servers stay listed as search entry points.

Regression tests (red → green captured): `read-stub-truncation`,
`todo-task-ownership`, extended `todo-nudge`, `task-capability` +
`task-capability-mcp`.

### O4 tidy-up items — decisions with rationale

- **`src/cli/tui-utils.ts` kept.** It is not a dead shell: its header documents the
  module split and it exists so `dist/cli/tui-utils.js` consumers keep working. It
  is a compatibility path with its own specs, so deleting it would be a breaking
  change justified by tidiness alone.
- **`src/tools/background-exec.ts` stays.** It is a tool implementation
  (`exec_background` / `exec_logs` / `exec_stop`) over the core process registry;
  `AGENTS.md` places built-in tools in `src/tools/` and the layering rules point
  inward (tools → core), so moving it into `core/` would invert the boundary.
