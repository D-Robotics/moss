# Super-agent 复杂功能演练：设备运维事件中心

状态：真实模型演练已执行；复杂业务验收未通过，独立控制面演练 10/10 通过。基线：`3c9b3ece`；增量恢复修复版本 `0.29.1`。演练分支：`codex/moss-superagent-eval`。详见 [结果报告](superagent-complex-evaluation-report.md)。

## 目标

让真实模型完成三个有持久化、去重和状态机约束的业务模块，组装成可通过 HTTP 操作的本地设备运维服务，再注入重复请求、追问、取消和调度器崩溃。模型使用用户指定的接口和 `deepseek-v4-pro`，不接触真实设备。

比较同一构建的两种入口：A 为原生 `moss task run/resume`，B 为 Super-agent 工单协调 + 同一原生 Moss worker。原版已有子代理、worktree、会话和 Task Runtime，这些不算新增优势。三个业务工单由验收方预先拆分，两组均可三个并发；为固定总 worker 预算，两组均不启用嵌套委派。不宣称自动任务拆解或自动合并。

## 业务工单

| 工单      | 模块         | 核心约束                                                                   |
| --------- | ------------ | -------------------------------------------------------------------------- |
| telemetry | 遥测接入     | 严格校验、全局事件去重、冲突拒绝、乱序窗口、JSONL 重放及残缺尾行恢复       |
| alerts    | 告警规则     | 高低阈值、迟滞、连续样本、重复/过期样本忽略、跨重启状态与持久化通知 outbox |
| queue     | 通知任务队列 | 幂等键、依赖、租约、过期重领、fencing token、指数退避、死信与重启恢复      |

具体 API 和边界在 `bench/scenarios/superagent-operations/TASKS.md` 固定。只允许模型修改相应业务模块。独立 oracle 位于工作区外，不允许模型修改验收代码、命令或选择工单。原生入口由验收方固定工单 oracle；Super-agent 从控制器数据库中的不可变 mandate 确定 oracle。

## 执行与证据

1. 从相同已提交脚手架创建两套仓库与独立工单 worktree；固定同一模型、权限、提示和并发度。
2. A、B 各运行三个真实开发任务。记录开始/结束、原生任务 ID、worktree、请求数、服务端 token 用量和独立 oracle 结果。单次样本只作功能演示，不作统计性能排名。
3. 验收方检查并收集三个限定文件，组装 HTTP 服务；由外部测试驱动重复遥测、告警、通知领取/确认，再重启服务检查持久化和不重复投递。文件收集是验收方的集成步骤，不归功于框架自动合并。
4. 在 B 上注入相同事件 ID、同 ID 改写、非授权请求、执行中追问、单独取消以及调度器 SIGKILL。检查稳定的 ticket/worktree/session、无盲目重放、显式重试和最终验收。原版已有的取消/恢复能力单列，不包装为新增能力。
5. 回放已完成输入，检查不增加业务执行。数据库、实际任务证据、时间线、测试结果、脱敏模型用量与最终对照表保存到被忽略的 `bench/results/`；可提交的报告不含凭据。

## 限额和判定

- 记录代理只转发到用户指定的服务与模型；原额度 100 次，用户已批准追加最多 60 次，总额上限 160。增量阶段硬性划分为基线修复 20 次、Super-agent 修复 20 次、故障演练 20 次，不互相借用。沿用上一轮 worktree、任务 ID、会话及同一 oracle；已验收模块不重做。单次输出上限 8192 token，两个入口均显式使用 thinking=disabled；每个 agent 回合另设轮次、工具调用和时间上限。服务端未返回 usage 的中断请求记为未知，不填 0，也不估算费用。
- 初始有效编码轮共用全局额度且顺序运行，实际 A/B 调用数不等，不能据此判胜负。追加阶段以相同的独立上限做修复验收，依然不能消除已有历史差异，最终只作功能与控制面演示。
- 每个业务任务最多 10 分钟；总演练工作预算 30 分钟，另加有界清理时间。失败或预算耗尽照实记录，不人工补写模型的业务答案。
- 通过要求：三个模块通过独立 oracle、HTTP 集成通过、演练未修改父工作区、验收代码哈希不变；控制面场景逐项记录通过或失败。
- 若 B 没有在编码质量或耗时上获胜，直接报告。可以主张的新增价值限于测得的持久化接单、跨工单授权/追踪和恢复行为，不等于模型更聪明。
- 若复杂业务未通过，故障额度可用于独立、简单的回执任务（`--lifecycle-only`）。它使用单独的固定 receipt oracle，结果只能证明控制面行为，不能补算业务模块或 HTTP 集成通过。
