## 方法说明

- 通过 `terminal_open`（PTY）+ `terminal_send` 驱动 `dist/cli.js`，`terminal_read` 拉取转录。
- 注意：`terminal_read` 是"重绘帧的线性回放"，同一帧内的重复行可能是重绘伪影；本文所有"重复"结论都
  与**不同事件**（两次 todo 更新、两次 run）交叉核对过。最终屏状态以最后一帧为准。
- 环境里继承了 `MOSS_DEVICE_HOST=rdk-sandbox.d-robotics.cc`（shell 已有），所以 ws-a 首屏出现相机占位提示；
  这是"已配置板卡"的预期行为，不计缺陷（ws-b 清空该变量后显示代码占位提示）。

请求「add a --verbose flag to cli.js and verify it prints more detail」中的审批：

- 第 1 次（Edit）：`Edit file /private/tmp/ux-ws-b/cli.js` + `╌` 分隔 + 带 `+`/`… (1 unchanged line)` 的 diff
  - `❯ 1. Yes / 2. Yes, and don't ask again for file edits (try to save in user config) / 3. No`
  - 状态栏 `● waiting for you … · 1/2/3 to answer · Tab to amend`。视觉清楚，选项可读。

  ——用户看不到命令结尾。

  3. Yes, for this path for the rest of this session`+`Esc or Enter = deny`。

     与上一个审批里 Enter = 1. Yes 相反；同一个键在两个相邻弹窗里语义相反。

长命令请求「run a shell loop that sleeps for 30 seconds then prints done」：full 模式下一个工具跑 30s，

退出：`/quit` 后只打印一行 `moss --continue`，随即回到 shell（无挂起、无心跳残留，干净）。

## Top 5 手感问题（按"影响 × 可改成本"排序）

### 1. 审批弹窗读不全/读不懂要批准什么（影响高，成本低）

证据：Bash 审批 `… && dif…` 截断；保护路径审批只有 `About to run non-literal command name`，命令不见；
同一次任务里 Enter 的语义从 "1. Yes" 变成 "deny"。

- 用户感受：要么盲批，要么停下来猜；安全提示反而不安全。
- 对照：Claude Code 的权限提示显示完整命令（换行不截断）+ 固定 default No。
- 修：审批 body 对命令行换行展示而不是 `clip` 单行（`src/cli/protected-path-prompt.ts:96` 的 `shown(hit)`
  在非字面命令时改为显示原始命令文本）；三个审批弹窗统一 Enter 默认；去掉
  `(try to save in user config)` 括号说明（`src/cli/approval.ts:989`）。
- 验证：PTY 跑一条 >120 字符的 shell 命令，截图断言命令全文可见；两次审批默认值一致。

### 2. 首屏同一条建议说两遍，且永不退休（影响中高，成本低）

证据：`⎿ Next: /init (detect this project, write AGENTS.md)` 与 composer `Try "/init" (…)` 同屏；
两次成功运行后仍是 `/init`（交互聊天不写 run ledger，见 `src/cli/onboarding.ts:365-375` 的分支只看 latest run）。

- 用户感受：像没人在看；首屏（含启动 3 行通知）在真正输入前就占了 8–9 行。
- 对照：Claude Code 首屏一行 tips + 一个 resume 入口；Cursor 首屏只有一个空 composer 提示。
- 修：Next 行与 placeholder 二选一（建议留 Next，placeholder 用中性 `Ask anything`）；把 `/init` 建议
  在"本会话发生过任意运行（chat 也算）"后退休——`welcomeComposerSuggestion` 增加"本会话已有消息"入参即可。
- 验证：空工作区首屏恰好一条 `/init` 建议；完成一轮后消失。

### 3. 启动先打 3 行开发者通知（影响中，成本极低）

证据：`[moss] Interaction mode: full … · /mode to change`（`src/cli/cli-locale.ts:375`）+
`[moss] Session logs live in .moss/. Add this to .gitignore …`（`src/cli/gitignore-suggestion.ts:35`）共 3 行。

- 用户感受：一进来像在看安装日志；而同样信息状态栏已常驻（`⏵⏵ full mode on`）。
- 对照：Claude Code 启动只有 1 行模式提示；Cursor 无此类通知。
- 修：mode 行已在状态栏就删掉；gitignore 建议降级为首次运行一次的 dim 一行（或只在 `.moss/` 真被 git
  跟踪时提），并把 3 行压成 1 行。
- 验证：PTY 冷启动首屏行数 ≤ 6；grep 不到 `.moss/skills` 第二行。

### 4. 工具结果仍是每条 2 行（影响中，成本低）

证据：`⎿ Read(test.js) · Read 7 lines · 42ms` 紧接 `… 7 lines · ctrl+o`（`src/cli/tui/transcript.ts:866`）；
数字重复（summary 已说 7 lines，续行再说 7 lines）。一次 run 3 个 Read = 6 行。

- 用户感受：24 行终端里一屏装不下 3 个工具调用；"已修成 1 行预览"的实际观感是 2 行。
- 对照：Claude Code 工具成功结果 1 行（`Read 7 lines`），需要展开才点开。
- 修：当 summary 已含行数时省略续行（或续行并入 summary：`⎿ Read(test.js) · 7 lines · 42ms · ctrl+o`）。
- 验证：PTY 跑 3 个 Read，断言工具结果总行数 = 3。

### 5. todo 清单同时出现在面板与 transcript（影响中，成本中）

证据：`⏺ Todo Write` 工具结果把 `⏺ 1/2 done / ✓ … / ◐ …` 整块打进 transcript，而 composer 上方已有
持久面板（`src/cli/tui/transcript.ts:1171` `renderTodoPanel`，app.ts:4218 渲染）；一次任务两次更新 ≈10 行。

- 用户感受：清单在同一屏出现两次；滚动时"进度条"被历史复制品干扰。
- 对照：Claude Code 计划/任务只在上方面板，transcript 只留一条工具调用。
- 修：todo 工具结果在 transcript 折叠成 1 行（`⎿ Todo 1/2 done`），完整清单只给面板；面板已有
  `finished` 分支，无需新状态。
- 验证：一次含 3+ 次 todo 更新的 run，transcript 里 todo 相关行 ≤ 更新次数（每次 1 行）。

## 已经感觉好的两点

1. **运行期反馈层**：Enter 后 <1s `✢ Working… 0s`；状态栏 `● running … · Esc to interrupt` + token/out/ctx；
   工具调用行带耗时；静默 16s 主动说 `no output for 16s — Esc to interrupt …`。这套与 Claude Code 同级。
2. **结果折叠与收尾**：`⎿` 一行预览 + `ctrl+o` 展开、Edit 的 `Added N lines` + 彩色 diff、Run Tests 的
   `ALL PASSED · 1/1 passed · 224ms`、收尾 `✻ worked for Ns · done H:MM` + 状态栏回 idle，读起来干净。

## 次要 / 未确认

- `✻ Still reasoning, waited 60s` 在长推理期连刷 60s（诚实但像卡住）；可考虑显示"正在推理（已等待 Xs）"
  并附一次心跳引用，而非重复同句。
- 状态栏 `90.4k in / 2.6k out` 与 `2% ctx` 并排时，"in" 是会话累计还是上下文占用心智不清；建议改为
  `session Σ` 或隐藏。
- 退出只打裸 `moss --continue`，建议加 `resume:` 前缀（与首屏 `Next:` 同语法）。
- 双按 Esc 清 composer / 双按 Ctrl+C 退出在自动注入下表现为"提示重复出现、未执行"；可能是自动化注入
  伪影，**需人工复验**，未计入 Top 5。
- 一轮里模型先写 `diff <(...)`（bash 语法）在 `/bin/sh` 下失败（`syntax error near unexpected token '('`）；
  这是 agent/环境行为，不是 TUI 缺陷，但失败结果的预览只给首行，用户要点 `ctrl+o` 才看到根因。
