# Cursor — capability inventory for gap analysis against Moss

Snapshot date: **2026-11-04**. Docs reflect Cursor **3.23–3.24** (October 2026 changelog entries; the newest in-product feature referenced is Annotate in 3.24.18).

Method: every row below was read from an official page fetched during this research (docs pages served as Markdown at `<url>.md`, plus `changelog`/`blog` HTML). URLs in the **Source** column are the canonical pages. Anything the docs do not state is marked `[unverified]` and kept out of the mechanism columns. Rows whose rationale is not stated in docs/blog say `inferred`.

Legend: `[unverified]` = not stated by official docs; `inferred` = my reading, not Cursor's stated reason.

## 10. What a competing harness would need to copy vs. what is Cursor-specific

### 10.1 Copy the mechanism (portable, no Cursor dependency)

1. **Rule frontmatter triad** `alwaysApply` / `description` / `globs` and the four semantic types with the documented truth table. It is the cheapest possible routing scheme and is fully file-based. (1.2–1.4)
2. **"File references are not inlined"** — rules point at templates, the agent reads with tools. Prevents stale duplicated content and keeps always-on tokens flat. (1.7)
3. **Nested `AGENTS.md` scoped by working directory**, and reading `CLAUDE.md` unconditionally for migration. (1.11–1.12)
4. **Explicit precedence chain** Team → Project → User, merged (not overridden), with an "enforced" bit for admins. (1.15)
5. **`SKILL.md` with `name`+`description` in always-on context and the body loaded on demand** — this is the whole token trick: description is a _routing hint_, body is a _resource_. Plus `paths` for file scoping and `disable-model-invocation` as the slash-command escape hatch. (2.5–2.8)
6. **Skill ↔ mode duality**: same artifact usable one-shot (`/skill`) or persistent (mode). Very cheap to implement once skills are content-addressed; big UX win. (2.10, 3.9)
7. **Migrate the old thing into the new thing** (`/migrate-to-skills`) instead of maintaining both forever. (2.13)
8. **Runtime approval taxonomy**: readonly (no prompt) / workspace-mutating (no prompt, git is the undo) / shell+MCP+web (prompt or classify) + a small set of always-prompt hard protections (browser, delete, outside-workspace). (4.2.1, 4.2.10)
9. **Policy as plain English** (`allow_instructions` / `block_instructions`) layered over a deterministic allowlist, merged user+project, team override. (4.2.5)
10. **Separate "what may run" (permissions) from "what a sandbox can reach" (sandbox.json)**. Two files, two mental models. (4.2.6)
11. **File-based MCP tool catalog**: names in static context, descriptions in per-server folders fetched on demand; per-server grouping so a `ls` shows a coherent unit. Copy the _measured_ justification too (−46.9% tokens). (4.3.8)
12. **Long tool output → file + `tail`/read**, never blind truncation. (5.8)
13. **Chat history as a file, referenced after compaction** so the agent can recover what the summary lost. (5.7)
14. **Context-usage breakdown by category** (system, tools, rules, skills, MCP, subagents, summary, conversation). Cheap, and it is the only way users learn the token economics. (5.5)
15. **Checkpoints as local, git-independent file snapshots that restore files only, not messages.** (5.12)
16. **Steering vs queueing as distinct verbs** (queue / send-now / deliver-at-next-tool-call). (5.13)
17. **Hooks with `matcher` + `timeout` + `failClosed` + a loop limit (~5) + exit-2-means-deny + `additional_context` injection.** The loop limit and fail-open-by-default are the non-obvious parts. (8.1.5–8.1.7)
18. **`readonly` + `is_background` + `model` in the subagent header**, 2-level nesting cap, resumable by agent ID. (9.1, 9.6, 9.7)
19. **`/goal` long-lived objective + `/loop` recurring + a pause key** as the self-driving primitive, rather than a separate "autonomous mode". (5.14)
20. **Worktree-per-agent with a declarative setup script** (`worktrees.json` with OS-specific keys, `$ROOT_WORKTREE_PATH`) and a machine-wide cap (25). (9.10)
21. **Environment-as-code for remote runs**: `install` (idempotent, at build time) vs `start` + `terminals` (runtime), disk-only snapshots, secrets injected per run. (6.4–6.6)

### 10.2 Cursor-specific (do not port; it is infrastructure or ecosystem, not harness logic)

1. **Instant Grep** as a custom search engine and the removal of embedding-based semantic search — the harness decision is "exact match + agentic exploration"; the engine itself is not portable. (5.2)
2. **Backend LLM classifier for Auto-review** with its own model routing (Gemini 3.5 Flash Lite / Haiku fallback) and read-only local tool access to judge scripts. (4.2.2–4.2.4)
3. **OS-level sandbox implementations** (Seatbelt profile, Landlock v3 + seccomp + userns, shipped AppArmor packages, `CURSOR_ORIG_UID` remapping). Portable _idea_, not portable _code_. (4.2.7)
4. **Cloud VM fleet**: provisioning, snapshots, Builds, artifacts, remote desktop, port forwarding, 300-repo environments, self-hosted pools. (6.1–6.8)
5. **Vendor-hosted control plane**: remote Agents API, Slack/GitHub/Linear apps, iOS app, dashboard team rules/hooks/allowlists, marketplace + `.cursor-plugin` distribution, team analytics, Cursor Blame. (1.14, 2.16, 4.3.11, 6.2, 6.9, 8.1.9)
6. **Per-model tuning of instructions/tools** ("tuning instructions and tools specifically for every frontier model"). Needs a model matrix and eval loop, not a feature. (https://cursor.com/docs/agent/overview)
7. **Root-cause bots**: Bugbot/Security Review/Rollouts with patch-ID dedupe, autofix loops capped at 3, deploy telemetry integrations. Ecosystem glue. (6.14–6.20)
8. **`/migrate-to-skills`, `/create-*`, `/review*`, `/statusline`, `/cursor-blame`** are _built-in skills_, i.e. content, not architecture. Copy the "ship the scaffolder as a skill" pattern, not the texts. (2.14)
9. **Branded equivalents of generic concepts**: Plans-in-home-dir, "Custom Modes", "Projects", "Memories" naming. Adopt the semantics, not the naming or the storage location defaults.

### 10.3 Gaps in Cursor's own docs (do not assume; re-verify before implementing)

- Numeric **token budget per rule / per skill**, and any "omitted skills/rules" notice in editor/CLI. Only Bugbot publishes caps (30k/100k chars) and only Cloud Agents publish a per-skill warning.
- Any **cap on MCP server/tool count**; the documented mitigation is the lazy file catalog, not a limit.
- **Plan-mode enforcement internals** (which tools are hard-blocked, whether a plan file is written before Build).
- **General IDE "Memories"** — docs only cover automation-scoped memories and the SDK memory hook.
- Current status of **codebase indexing/embeddings** in the IDE; docs describe Instant Grep only, and the SDK states semantic search is removed.
- Whether hooks can rewrite tool arguments for HTTP MCP `preToolUse` (docs say `updated_input` is ignored there) and whether `beforeSubmitPrompt` can rewrite prompt text (changelog says "modify prompts", docs imply validation).
