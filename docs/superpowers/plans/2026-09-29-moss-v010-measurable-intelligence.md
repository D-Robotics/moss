## 1. 工作流(五件)

### W1 基准难度分层(先测得出失败——一切的前提)

- 新增 **hard 层任务 ≥8 个**,设计目标是当前 moss 可测量地失败:
  - 隐藏耦合重构(改 A 处须连带改 B 处,直接改则测试挂)
  - 歧义规格(两种解读都"合理",只有一种通过验收;考验澄清/多数派)
  - 多假设调试(症状有 ≥3 个可能根因,须逐一排除而非赌第一个)
  - 长上下文精确召回(100+ 文件中引用 3 个具体事实,compaction 之后仍须答对)
  - 并发 bug(竞态只在特定交错下复现,须写确定性测试暴露)
  - 依赖冲突(两个依赖要求互斥版本,正确解是降级/替换而非硬装)
  - 规格自相矛盾(任务描述含 X 与非 X,正确行为是指出矛盾而非盲做)
  - 性能回归定位(引入 O(n²),须用测量证据定位而非猜)
- **失败基线采集**:v0.9 代码跑 hard 层(samples=3),要求通过率 <70%;若 moss 意外全过,任务加难直至测得出失败(诚实校准,不造虚假难度)
- **难度加权能力分**:`score = Σ(pass_rate × weight)`,hard=3/easy=1,进 summary.json
- 验收:hard 层 ≥8 任务;v0.9 失败基线落盘;能力分进 summary;easy 层保持 100%

### W2 test-time compute 引擎

- **best-of-n 关键编辑**:plan/关键 edit 生成 n 个候选(默认 2),结构化评审器逐项对照验收标准+证据引用择优;`run.budget` 内触发(预算不足自动降为 n=1)——与 v0.9 的护栏咬合
- **self-consistency 歧义处理**:歧义任务先并行 2-3 个解读,不一致→多数派并在结果中声明假设;headless/自主模式不问用户(交互模式可问)
- 实现挂点:completion gate(评审器)、fan_out(并行)、run.budget(成本)
- 验收:hard 层加权分提升 ≥10pt(噪声带外);best-of-n 平均成本增幅 ≤50%,预算不足时正确降级

### W3 多 agent 舰队:并行实现 + 交叉审查

- fan_out 新增 **implement+review 模式**:实现者产 diff,审查者拿 diff+验收标准逐项对照(独立子代理),分歧处回流修订
- **结构化证据门禁**:C3 的"合并须带证据引用"从提示词层升级为机器可查(合并产物解析出 per-child 引用,缺失即拒绝合并、要求重做)
- 内置专家 profile:debugger / refactoring / test-writer 三个(expert-registry 已是声明式,加声明即可)
- 验收:hard 层多文件任务提升;bench 转录中出现可观测的"审查→修正"回路

### W4 自适应推理预算

- 难度信号:首轮失败 / 编辑冲突 / 多文件触及 → 提升 reasoning;连续顺利 → 降低
- 配置面:`agent.reasoningBudget = 'off' | 'adaptive' | 'high'`(默认 adaptive)
- 验收:hard 层提升或持平,且**平均 tokens 不增**(难度自适应生效的直接证据是钱花在刀刃上)

### W5 能力回归门

- bench 增 `--score`(加权分)与发布门:**v0.10 hard 层加权分 ≥ v0.9 基线 + 10pt**
- **每个引擎单独开/关 A/B**(samples≥3):提升不足噪声带外 5pt 的引擎**默认关闭**、留配置开关——诚实交付,不为了讲故事保留无效引擎
- 验收:全部 A/B 数据落 bench/results;easy 层 100% 不回退

## 2. 验收总门(v0.10 tag 条件,缺一不发)

1. hard 层 ≥8 任务,且 v0.9 失败基线在其上 <70%(基准测得出差异的前提成立)
2. v0.10 hard 层加权分 ≥ v0.9 基线 + 10pt(噪声带外的真实提升)
3. 提升不靠烧钱:平均成本增幅 ≤50%,run.budget 护栏全程生效
4. 每个引擎有开/关 A/B 数据;提升不足噪声带外 5pt 的默认关闭
5. `npm run verify` 全绿;easy 层 11 任务保持 100%
