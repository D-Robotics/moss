# Moss 端到端物理任务案例执行计划

> **For agentic workers:** Use the current runtime's plan-execution workflow to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** 留下同一 Moss 长程任务从独立部署仿真到连续动作测试、诊断修复和最终复验的真实证据，并制作首个可运行版本与最终版本同框 GIF，更新现有 PPT 第 3 页。

**Architecture:** Moss 在服务器独立工作目录自行部署 LIBERO 原生环境并编写动作策略。冻结的验收父进程独占仿真，策略子进程只通过 JSON 观测和 7 维动作交互。所有测试保留版本、观测、动作、物理时间、官方判定和原始帧；独立复验后选择最终版本。

**Tech Stack:** Moss v0.31.0、现有 DeepSeek 配置、Python、LIBERO、robosuite、MuJoCo、FFmpeg、现有 Spaces 演示文稿。

### Task 1: 固定实验与取证协议

**Files:** 输出目录 `moss-physical-e2e-run/protocol/evaluate.py`、`protocol/README.md`、`run-contract.json`。

- [x] 创建独立目录，不改已有环境、任务、评分与后台工作。
- [x] 固定任务为打开顶层抽屉并把碗放入，使用官方 BDDL、seed 1、20 Hz OSC_POSE；最多 1500 步，说明与原 1000 步协议不同，不用于榜单比较。
- [x] 冻结验收器和首次初态，记录 SHA256。仿真状态仅在集初设置，后续只经 `env.step()` 推进。
- [x] 分别记录官方成功与附加物理交付：真实拉开抽屉、松开碗、连续保持成功 20 步。动作越界、超时、异常均保留失败报告。
- [x] 预先定义首版为首次可运行的策略 episode。若一次成功，保留事实，不制造失败。

### Task 2: 启动一个真实 Moss 长程任务

**Files:** 服务器独立工作目录的 `AGENTS.md`、`goal.txt`、`run.log`、`.moss/`、Moss 创建的部署/策略文件。

- [x] 只提供高层目标、协议和官方源码缓存位置，不提供历史求解器、抓取姿态或已知策略。
- [x] Moss 自行建虚拟环境、安装和配置仿真，再编写控制程序、运行测试、读报告、修改复验。使用缓存须披露。
- [x] 初始运行设置回合与 50 分钟墙钟上限；Flash 多轮仍失败后，同一目标以 Pro 后端追加 30 分钟。每次启动和干预单独记录，监控时不修改策略、不提供中间动作提示。
- [x] 从真实会话统计部署调用、测试次数、代码版本、唯一工具调用、持续时长和诊断修复链。

### Task 3: 独立复验和展示

**Files:** 输出目录 `evidence/`、`first-final.gif`、现有 Spaces 演示文稿第 3 页。

- [x] 核对验收器、环境源、BDDL、初态与资产哈希未变。

- [x] 用真实仿真帧同框制作 GIF，统一镜头、时间标尺和播放速度。清楚标记停止或保持末帧，不生成机器人动作画面。
- [x] PPT 用一条真实工作时间线说明部署、测试、诊断和复验，引用实际时长/调用数；不把仿真时间写成长程工作时长。
- [x] 渲染检查改动页面，验证 GIF 帧数、时长、标签和原始记录一致后交付。
