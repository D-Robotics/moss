# TUI Feel Benchmark Implementation Plan

**Goal:** Measure real visible composer readiness, typing echo, and streaming interruption at multiple PTY sizes without a provider key or a false successful run.

**Architecture:** Reuse the existing local stub and `screen.py` terminal model. Add opt-in event-driven sampling to `Session`, execute and validate the JSON scenario steps in `driver.py`, and make `run.mjs` propagate missing prerequisites and driver failures. Preserve existing layout-probe behavior.

**Tech Stack:** Node.js, Python standard library, existing pyte dependency, real PTY and the built Moss CLI.

---

### Acceptance

- With a built CLI, the default command runs the stub and actual CLI at 100×30 and 70×24, verifies an actionable composer, measures typed text on its composer row, submits `longstream`, observes streamed content, interrupts the active run, verifies the stub saw the connection close before finishing, and verifies the composer remains usable.
- Timing uses a monotonic clock: CLI spawn to visible composer and raw PTY input; each PTY write to the first subsequently observed qualifying terminal frame. Requiring raw mode prevents kernel echo from impersonating application response. Output explains that it measures observation after PTY/pyte processing, not a display, network, or human reaction benchmark.
- Malformed, empty, or failed steps; child exit; timeout; missing build, Python, or pyte must return nonzero and must not publish a passing report.
- The CLI runs from a temporary copy of the build with isolated home/workspace and no `.env` ancestors; fallback providers are disabled. No production credentials or external provider are used. Existing layout probes retain their defaults.
