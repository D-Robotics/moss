## v0.11 规格智能:拒绝盲从(Spec Intelligence)

**定性**:让 moss 在动手前先审计规格——矛盾要指出、陈旧文档要对质代码与测试、不可复现的投诉要以证据回绝。"实施了矛盾规格"与"漏改了耦合"同等级别地算失败。

### 工作流

| 项                  | 内容                                                                                                                                                                                            | 验收                                                                                                                      |
| ------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| S1 规格一致性预检   | 实施前的结构化要求审计:枚举显式要求→两两一致性检查(输入空间重叠而输出要求互斥即矛盾)→与代码/测试现状对质(规格声称与被锁定的测试冲突即陈旧)→产出 AUDIT 报告;矛盾确认时正确行为=写报告+零代码改动 | mock 单测锁:矛盾对检出、无矛盾规格零误报(误报率 0——误报会阻碍正常实施)                                                    |
| S2 投诉调查协议     | bug 类任务先复现:跑声明的验证→能复现→修;不能复现→INVESTIGATION 报告(证据:命令+输出)+零代码改动;禁止"改点东西显得干了活"                                                                         | 单测锁复现/不可复现两分支;bench 转录可见复现尝试                                                                          |
| S3 诚实契约进提示层 | 系统提示明确:"实施了互斥要求之一=失败;指出矛盾并停手=成功";completion gate 增"报告型完成"合法路径(无代码改动+报告文件存在=合法 done)                                                            | 提示与 gate 的 spec 锁                                                                                                    |
| S4 A/B 与门         | hard 层全量 samples=3,引擎开/关                                                                                                                                                                 | 诚实族 4 任务各 ≥2/3(现 0/3);hard 总分 ≥75(现 60.6,>+14pt);easy 100% 不回退;误报检查:easy 层实施类任务轮次/成本无显著上升 |

### 明确不做

- 不做通用 NLU 矛盾检测(只做"输入空间×输出要求"的结构化规则)
- 不改 bench 判分(夹具不变,能力必须真实提升)

## v0.12 模型路由:成本-质量帕累托(Smart Model Routing)

**定性**:同一任务内,易轮次用便宜模型、压力轮次切强模型、探索型子代理用廉价模型、实施型用强模型——把 v0.11 验证过的能力在每个价位上最大化。前提:v0.11 过门(honesty 引擎落地,hard ≥75)。

### 工作流

| 项                 | 内容                                                                                                                                  | 验收                                                                                                                    |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------- | -------------------------- |
| R1 模型目录与价位  | config 面:`models: [{id, provider, tier: cheap                                                                                        | balanced                                                                                                                | strong}]`(env 覆盖);默认继承现有单模型配置(零配置不破坏) | 目录解析 spec + 零配置回归 |
| R2 轮内自适应路由  | 复用 v0.10 W4 的压力信号:干净轮→cheap,压力(验证 streak/red-verify/连续错误)→strong;切换在轮边界生效(不中途换)                         | 单测锁升降级;A/B                                                                                                        |
| R3 舰队分价        | fan_out/create_subagent 按 scope 自动选档:explore/verify→cheap,full→balanced/strong(可显式覆盖);best-of-n 候选默认 cheap、评审 strong | 单测 + bench 转录里每子代理实际模型可见                                                                                 |
| R4 成本计量        | llm_usage 事件带 model 与 tier;bench summary 增 `cost per pass`(按模型价位加权);/usage 分模型统计                                     | 计量 spec;数据落盘                                                                                                      |
| R5 帕累托 A/B 与门 | 三臂:全 cheap / 全 balanced / 路由开启                                                                                                | **路由臂 hard 分 ≥ 全 cheap 臂 +5pt 且成本 ≤ 全 balanced 臂 70%**(双条件同时过);easy 100%;A/B 数据落盘,不过则路由默认关 |

### 明确不做

- 不做跨厂商聚合/多网关负载均衡(单网关多模型即可)
- 不做训练/微调

## v0.13 / v1.0 生产就绪(Production Ready)

**定性**:把三轮能力/效率成果封进稳定的嵌入面。前提:v0.12 过门或按数据决策跳过路由(帕累托双门不过则该引擎关停,v1.0 不依赖它)。

### 工作流

| 项              | 内容                                                                                                               | 验收                                                                       |
| --------------- | ------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------- |
| P1 SDK 接口冻结 | 梳理 `src/index.ts` 公共面→契约 spec 套件(每个导出的行为锁)→semver 政策入 AGENTS.md(major/minor 界定)              | 契约 spec 全绿;breaking-change 探测:对公共面做一次故意破坏性编辑,CI 必须红 |
| P2 API 参考文档 | 从 d.ts 生成 API 参考 + 3 个嵌入示例宿主(headless JSONL 驱动 / REPL 宿主 / 自定义工具+钩子),示例可直接 `node` 运行 | 3 示例各在干净目录实跑通过;文档与 d.ts 同步检查                            |
| P3 支持矩阵     | Node 版本×平台×provider 矩阵进 CI 矩阵跑精简 verify(子集 spec)                                                     | 矩阵 CI 绿;不支持组合明确标注                                              |
| P4 v1.0 发布门  | 全量 verify + 全量 bench(easy 100%+hard ≥ v0.11 水平)+ 嵌入示例跑通 + 契约 spec 绿                                 | 四条全过发 v1.0.0;缺一不发                                                 |

### 明确不做

- 不做云端服务/托管;不做 UI(边界不变)
- 不引入 memory/skills/mcp 等已删除子系统
