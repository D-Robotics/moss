### 0.4 Codex capture caveats (carry these; do not over-cite R2)

R2's own §0 states them; reproduce them whenever a codex colour or model-behaviour claim is quoted:

- **NO_COLOR trap (verbatim intent).** The capture agent's parent shell had `NO_COLOR=1` and
  `TERM=dumb`, and the driver inherits the parent environment for `--bin`, so an unprefixed run yields a
  **completely colourless screen**. The first capture round (`scratch/cx-s1*`, `cx-size80/120`,
  `cx-turn4/5/6/7/8`, `cx-menus`, `cx-slash*`, `cx-keys`, `cx-diff`) is therefore **text-valid,
  colour-invalid**. All colour conclusions come from the later `env -u NO_COLOR` rounds
  (`cx-color*`, `cx-csize*`, `cx-diff2/3/4`, `cx-replay*`, `cx-exit*`, `cx-mcp`) and were cross-checked
  against raw SGR bytes via `--rawlog`.
- **pyte does not model SGR 2 (dim)**, so `.style` dumps cannot prove “dim” claims; those come from raw
  bytes only.
- **The default model was broken.** The real config (`--realhome`) points at `deepseek-flash@latest`,
  which the gateway rejected (`模型不存在`), so **every real model turn used
  `-m glm-5.3-flash -c model_reasoning_effort="low"`**. No R2 claim about model _choice_, effort
  defaults, or answer quality is portable to moss. The rejection itself is usable evidence for the
  retry/error path (K15).
- **Real-config side effects were written**: `~/.codex/history.jsonl` gained draft entries,
  `~/.codex/config.toml` gained an omx plugin `hooks.state` trust hash and
  `[tui] session_picker_view = "comfortable"` (written by `ctrl+o` inside the picker). No trust entry
  for the probe directories was written, codex was not upgraded, and no codex turn touched the moss
  repo (all turns ran in `/private/tmp/cx-ws`, `/private/tmp/cx-git`, `scratch/codex-ws`).
